# 深度双结果、Agent 裁切与画布搜索 · 1005k

本批把视频深度接入正式普通视频节点，并补齐结果保存与失效保护。全部运行在本机隔离数据上；官方页面、安装包与公开文档只作参考，未调用原站生成服务或真实付费模型。

## 视频深度

- 正式模型菜单选择 Depth Anything Video，旧提示词清空且只读，语音禁用，规格为视频编辑、比例/清晰度/时长自动，数量支持1/2。[源码与官方证据](VIDEO-DEPTH-NODE-ENTRY-20261005.md)。
- `fal-video-depth-native` 保留单任务格式；双结果使用持久父任务和两个独立子任务。派发身份先保存，重启/查询仅 GET 已知子任务，取消先写屏障。无持久目录的服务只声明单结果能力。[协议与配置](VIDEO-DEPTH-NATIVE-20261005.md)。
- 多变体写当前目标的视频历史；铺开/堆叠沿用正式结果规划。已有媒体目标保持原内容，空目标可复用首个结果。来源可以是独立的上游视频节点。
- 派发与回填校验来源、目标、输入连线、节点参数及项目；来源编辑、删除重建和切换项目拒绝迟到结果。实际媒体解码后核对结果数量、尺寸、时长。保存失败保留同一结果回执，仅重试保存，不重新生成或重复创建节点。
- 失败签名忽略终态清理掉的 `generationRecovery`；按实际“捕获失败回执→清理”顺序，失败提示继续显示。用户编辑或新任务仍使旧提示失效。

Computer Use 使用 `src/features/video-depth/qa/main.html?mode=pipeline&session=depth-native-1005k-root1` 与独立 QA 服务。通过正式按钮完成三次双结果任务：第一批多变体；第二批故意保存失败后用任务托盘重试；第三批铺开。后台合计6次供应商 POST，保存重试未增加提交。真正重新加载后保留来源、原目标与两个铺开结果；原目标保留两批各两个版本。完整预览从“播放”切为“暂停”，最终 `currentTime=duration=2`、`ended=true`，实际像素64×48。结果是仓库固定灰度视频，仅验证合同与媒体链，不证明深度模型效果。

共享应用与布局的定向验证覆盖三种模式和空/已有目标、保存失败、项目切换、异步来源变化；后端另有真实 routed gateway→持久重启→仅 GET→两个不同MP4归档及原字节回读的回归。本轮不重复全量测试；堆叠本轮为代码/事务测试，未再走一遍浏览器。

## Agent 平台尺寸

真实原应用拖动时，同宽高比的旧选项会取消，其他比例保持；指针取消与坐标限制沿用已有合同。浏览器将 portrait 从x313拖到451，portrait_alt取消；确认生成450×800、800×800、1200×675三张真实PNG，源图加结果共4节点、一次撤销、一个回执，成功按钮禁用。原HTML按SHA限定派生，没有重写原设计。[专项记录](AGENT-PLATFORM-RESIZE-DRAG-SELECTION-20261005.md)。
