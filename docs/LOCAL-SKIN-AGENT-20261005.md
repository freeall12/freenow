# 皮肤编辑与 Agent 本机验收 · 2026-10-05

本批完成正式皮肤面板三档、独立任务合同、Agent 审批与增强节点保存流程；**不是 Enhancor 原生适配完成，也不构成全站一比一完成声明**。所有生成验证使用公开合成 PNG、固定 Agent 回复与本机供应商边界，没有真实 Key、付费请求、原站生成调用或用户素材上传。

## 参考与运行边界

- 本机官方包 `course-api-base-url-CGXqZmAy.js`、`index-BsHyQ2qj.js` 确认三档为 Enhancor。细节使用 `enhancor-detailed`，标准/重度使用 `enhancor-realistic-skin` 的固定语义。[精确参数和公开协议](SKIN-EDITOR-NATIVE-CONTRACT-20261005.md)。
- 官方 Web 实操更多→增强→皮肤：默认细节、三档菜单、重度警告“过度增强可能会改变图像”、切换高清放大后返回仍保留标准、Escape关闭。只新建并撤销本次空增强节点，未点击生成；原画布内容保持。
- 皮肤面板官方实测 `400×175.97`，本地 `400×175.8759` CSS px，沿用原SVG和定位公式。本地两级Escape先关菜单并回焦，再关面板。
- 运行继续使用本地 freenow 入口；供应商服务与原站无运行依赖。本批没有更换框架或新增生产依赖。

## 实现与交叉审阅

`image-enhance-ui.mjs` 保留面板、模式和重度警告，新增配置预检、准备取消、来源保护与真实任务状态；三个增强面板移除虚构积分和固定一分钟时间。`src/features/image-skin/` 分离模式合同、媒体准备、来源守卫和结果应用，供 Agent 与面板共用。

专用协议 `skin-tasks-v1` 只接受 `image.skin`、空提示词、明确mode、完整原尺寸PNG和一个结果。单图上限32 MiB及32×1024×1024像素；前端在原尺寸规范化，服务端校验实际CRC、zlib、scanline和解码像素后归档。HTTP响应预算64 MiB，其他普通任务仍为原1 MiB。普通 `tasks-v1`、OpenAI/fal 图片路由不会默认启用皮肤编辑。

Agent 的 `generation_submit` 使用显式 `skin:{mode}`，可新建相连增强节点，也可指定仅连接此来源的既有增强节点。正式确认卡披露来源、模式、目标及真实服务条件；原任务ID先写入持久会话，随后才读取完整PNG并提交。新目标在实际应用结果时创建，保存失败保留同一目标和版本，只重试保存。

交叉审阅修复三项边界：

1. 每次审批来源校验都检查完整图片范围，覆盖审批后新添的裁切、选区、mask、projection等12字段，阻止派发及旧结果覆盖。
2. `runInPlace.verifyRequest` 绑定最终PNG、模式和原任务身份；`recover` 查询前后检查来源，带任一种守卫的调用不加入其他正在查询的恢复请求，避免跳过自己的验证。
3. 首回执先验证可信任务ID并持久化，再验证PNG。坏PNG仍拒绝发布，但可在服务重启后GET原任务取回修正结果；不丢失查询身份，不重复POST。
