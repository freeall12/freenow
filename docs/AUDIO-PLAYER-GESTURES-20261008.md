# 音频播放器与画布手势 · 2026-10-08

已修复播放器外围空白不能直接拖动音频节点的问题。波形保留左键播放定位，播放按钮保留独立事件；波形的中键/右键回到画布平移/菜单逻辑，预览播放器的事件仍留在预览内。没有增加按钮、图标、外部调用或依赖。

## 官方依据

已读取官方 Web 捕获的 `reference/vendor-pkg-canvas-CvuTKiTt.js`：`ABe` / `qD` 在正式节点调用 `EZ` 时 `allowWaveformSeek:!0`；`lze` 外层没有整块 pointer 拦截，三个播放按钮通过 `nodrag` 与 `onPointerDown:jA` 停止传播。`cze` 图库预览才禁用波形定位，不能混用为节点合同。原始 bundle 只作本机来源，不成为运行依赖。

本地 `makePlayer` 此前在 wrap 的所有 pointerdown 一律停止传播，而所有节点标题也禁用了鼠标命中；所以 10 月 7 日画布截图演示中，只能多选音频与文本一起移动。修复只在节点播放器设置 `dragSurface:true`，依据当前命中对象和鼠标键保留必要的隔离，不重写画布坐标/历史逻辑。

## 实际浏览器

使用独立 `localhost:4195` 本项目服务、无供应商环境及隔离后台数据。4173 当前属于其他项目，不作为 freenow 入口。`gesture-main.html?session=audio-1008-upload` 使用正式生产脚本和独立项目/素材 IndexedDB；通过真实文件选择器上传公开合成 3 秒 WAV，没有直接修改运行时节点。

- 顶部空白实际拖动 120 / 50 屏幕像素：逻辑位置从 120 / 160 到 240 / 210，波形保持零。初轮一次撤销及重做精确恢复。
- 按钮间空白再拖动 80 / 40：位置到 320 / 250，一次撤销回 240 / 210。
- 波形实际拖动到 2.238805 秒，节点位置不变；实际播放状态切到暂停按钮、播放位置继续前进；后退/前进在 3 秒文件中分别到 0 / 3。
- 真实上传源保存为本地素材；刷新后仍完整解码为 3 秒，节点位置 240 / 210、文本 580 / 160。浏览器重新建立本机 blob URL，无需原站资源。
- 与普通节点标题接线共同验证直接改名、标题撤销/重做及刷新回读。Enter 后焦点现已回到节点，可立即 Cmd+Z / Cmd+Shift+Z；Escape 取消草稿并保留节点焦点。懒创建补修后再次刷新，未选中节点为零标题输入，首次选中才创建输入，Enter 与立即撤销/重做均再次通过，见[标题记录](../src/features/canvas-node-titles/README.md)。
