# 本地素材工作流补齐 · 2026-10-03

本批优先功能开发，只做改动相关检查和实际操作，不跑全量回归、不重复打开 GitHub 确认。

## 主体库

个人主体改存现有 IndexedDB records；旧 localStorage 只读迁移，不删除原数据，不因迁移释放原占用。UI、Agent、生成提示词读取同一份已提交内容，个人主体继续跨画布共享。保存/改名/归档等到真实提交才成功，失败保留草稿，导航等待在途写入。原操作回执与恢复指纹保持兼容，详见 [存储合同](AGENT-STORAGE.md)。

共享提示词编辑器的打包入口将主体 store 保持为外部 ESM，避免打包副本形成第二份空缓存。主体悬停卡等待读取，销毁后不再更新；重新构建 `assets/agent-editor.js`。

## 视频延长

`video.extend` 素材准备移入生产 TaskService 的配置检查之后。来源和视频参考若有 `clip`，使用既有 FFmpeg 接口先得到真实裁片，记录原 `sourceRange`，去掉需要下游再次裁切的指令。真实时长/分辨率来自媒体解码；本地 URL 通过共用有大小上限、超时和取消的传输层转为实际数据。

来源或参考素材发生变化时停止准备/应用。没有配置此操作时不读取媒体。操作仍需要支持 `video.extend` 的任务服务；此次没有新增原生延长供应商，不能把本地裁切验证当作模型生成成功。

## 图片生成来源

擦除、重绘、扩图、增强/皮肤、抠图的自定义结果回填现在保留实际生成模型、提示词、任务 ID 和全尺寸媒体来源。切换图片版本使用该版本保存的信息，导入图不会借用下一次生成参数。细节见 [媒体来源](../src/features/media-preview/README.md)。

## 证据

- 图片编辑与版本来源的 36 项相关检查通过；主体 Agent/存储 18 项检查通过，并追加恢复序列化兼容断言；视频延长 8 项相关检查通过。没有运行全量测试。
- 独立只读审查覆盖来源回填、重复裁切、存储失败和导航等待，没有剩余可执行问题。
- 官方现场只核对新版片场空状态与导入菜单：glTF 2.0、.gltf/.glb、立方体/球体/四棱锥、合并上限12MiB及自动保存。没有修改官方场景，也不把此范围算作片场全部验收。
- 本地实际操作在隔离 namespace 中进行，未知 API 和外部 fetch 被阻止。视频来源是公开合成三色视频：选区2–4秒，真实 FFmpeg 裁切后只提交2秒绿色片段，任务 `posts:1`、`sourceClip:null`，固定生成响应回填并实际播放，预览显示320×180、0:02。固定响应返回输入裁片，仅证明准备/回填链路，不证明视频延长效果。
- 夹具让主体 localStorage 写入抛出 QuotaExceededError；通过真实界面新建主体、选入视频、保存、刷新、重新打开，主体仍在 IndexedDB。未填满或清空用户存储。
